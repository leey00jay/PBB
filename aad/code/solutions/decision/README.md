# 판단 파트 — decision

**어느 경로를 어떤 속도로 따라갈지, 언제 멈출지 결정합니다.**
인지 결과를 받아 경로를 만들며, 액셀과 조향의 실제 수치는 제어 파트가 계산합니다.

## 담당 파일

- `lane_planner.py`: 중심 경로 생성, 차로 폭 추정, 경로 이상 검사, 주행·정지 결정.
- 입력과 출력 형식: [interfaces.py](../interfaces.py)의 `LaneObservation`, `DrivePlan`.

## 현재 동작

- 양쪽 경계가 유효하면 중간을 중심 경로로 만듭니다.
- 한쪽만 보이면 초기 3.5m 또는 이전에 추정한 차로 폭을 사용합니다. 이는 양쪽을 모두 검출한 결과가 아닙니다.
- 경로가 너무 멀거나 갑자기 이동하거나 차로 폭이 비정상이면 정지합니다.
- 처음 30프레임은 준비 상태로 정지합니다. 인식이 끊긴 뒤에는 유효한 경로 5프레임을 확인한 후 재출발을 허용합니다.
- 실행 파일의 `desired_speed_kmh`는 현재 80km/h입니다. 판단 파트의 상한은 80km/h, 한쪽 차선만 보일 때의 상한은 40km/h입니다. 요청 속도가 더 낮으면 그 값을 사용합니다.
- `Polynomial.deriv()`로 경로 곡률을 계산하고 전방 커브의 허용 속도와 감속 거리를 반영합니다.
- 실제 프레임 시간 `dt`에 맞춰 목표 속도 상승은 1.5m/s², 하강은 3.0m/s²로 제한합니다. 주행 불가 판단은 즉시 목표 0과 제동을 지시합니다.
- 교차로 회전 경로 선택, 신호등·장애물 대응은 아직 구현하지 않았습니다.

## 다음 작업

1. 새 인지 코드가 현재 차로를 표현할 수 있게 되면 그 결과를 중심 경로로 연결합니다.
2. 새 검출, 잠시 유지한 결과, 인식 상실에 대해 주행·감속·정지 정책을 정합니다.
3. 정지와 재출발이 짧게 반복되는 상황을 기록하고, 재출발 조건을 검증합니다.
4. 목표 경로와 목표 속도에 결정 이유를 함께 남깁니다.

`tracked`라는 문구 하나만 보고 주행을 허용하지 마세요. 실제 현재 차로인지와 입력 결과의 유효성도 판단에 필요합니다.

## 전달 형식

`LanePlanner.plan(observation, desired_speed_kmh, dt)` → `DrivePlan`

| 항목 | 의미 |
|---|---|
| `trajectory` | 차량 기준 Nx2 경로, 미터. x 전방, y 오른쪽. 경로가 없으면 `None` |
| `target_kmh` | 목표 속도, km/h |
| `drive_allowed` | 경로를 따라 주행하도록 허용했는지 |
| `status` | 주행·정지 이유 |
| `stop_brake` | 현재 테스트에서 정지 시 사용하는 제동 값 |
| `lane_width_m`, `left_valid`, `right_valid` | 판단 근거와 화면 표시 정보 |

인지의 카메라 좌표를 차량 좌표로 바꾸는 기존 계산(x + 0.5m, y 부호 반전)은 이 파일에서 한 번 수행합니다.
준비·재확인 중에는 경로가 있어도 `drive_allowed=False`일 수 있습니다. 경로 존재 여부만으로 출발시키면 안 됩니다.
